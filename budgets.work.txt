WHAT WAS IMPLEMENTED
- Optional monthly budget per category plus an optional overall monthly budget (covers all spending, including unbudgeted categories).
- Dashboard "Budgets" card (directly below the summary cards) for the current calendar month:
  - Header shows the month and "day N of M".
  - One row per budgeted item (Overall first, highlighted; then categories in CATEGORIES order): icon, "$spent of $budget spent (NN%)", a progress bar, and a status line with icon + text.
  - Statuses: On track ($X left); On pace to exceed ($X left, on pace for $P); Budget used up (spent exactly == budget); Over budget ($X over). Color is never the only signal: every status has a text label and an icon.
  - Pace projection: spent / dayOfMonth * daysInMonth (today counts as elapsed). On the last day the projection equals actual spending.
  - Progress bars use role="progressbar" with aria-valuenow (capped at 100) and an aria-valuetext containing the full text summary and status.
- "Set budgets" / "Edit budgets" button opens a native <dialog> modal (components/ui/Modal.tsx) with a form: overall field + one labelled field per category, blank = no budget. Validation: positive numbers, max 2 decimals, > $0, <= $1,000,000, with per-field error messages linked via aria-describedby, focus moved to the first invalid field on submit, values normalized to 2 decimals on blur (same pattern as ExpenseForm). Shows a live note with the total of category budgets and warns (non-blocking) if they exceed the overall budget. "Clear all" empties every field; saving an empty form clears budgets.
- Empty states: "No budgets yet" (EmptyState with Set budgets button) when nothing is configured; "No spending yet this month" note when budgets exist but this month has no expenses (rows then show $0 spent / full budget left). The card only appears when the dashboard has any expenses at all (the existing dashboard-wide "No expenses yet" empty state is unchanged).
- Persistence in its own versioned key with schema checks that drop malformed entries (invalid/unknown categories, non-numbers, <= 0, > max, more than 2 decimals, wrong container types) and count them; corrupted JSON / wrong top-level type yields empty budgets + an error. localStorage unavailable on read and quota/private-mode failures on write are caught and surfaced as toasts. Cross-tab sync via the `storage` event. Skipped-record and error toasts are reported once (StrictMode-safe), mirroring ExpenseProvider.

KNOWN LIMITATIONS
- Budgets are a single set applied to every month (no per-month history or rollover); progress is always for the current calendar month.
- Pace projection is a naive straight line; early in the month (especially day 1) a single purchase can flag "on pace to exceed". Large one-off bills (rent) skew it.
- "Exactly at budget" uses strict equality on cent-rounded values (sums go through sumAmounts, so this is reliable).
- The card is not shown when there are zero expenses overall (dashboard's existing empty state takes over), so budgets can't be set before the first expense is added.
- The month/day is computed at render time; a dashboard left open past midnight on the last day won't roll over until something re-renders/reloads.
- Category-sum > overall budget is a non-blocking warning only.
- Budget state is local to the card's hook (not app-wide context); if another page later needs budgets it should lift useBudgets into a provider.
